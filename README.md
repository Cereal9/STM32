# STM32L432KC Bare-Metal Firmware

Bare-metal (no HAL, no RTOS) firmware for the **STM32L432KC** (Nucleo-32,
Cortex-M4F) built with a hand-written `Makefile` and **STM32CubeCLT**.
Register access goes straight through CMSIS device headers — no vendor
abstraction layer in between.

```
│   │   │                         your own peripheral drivers live here side
```

## What's configured

### Toolchain — STM32CubeCLT

Compiler, assembler, linker, `objcopy`/`objdump`/`size`, GDB, the flash
programmer, and the GDB server all come from **STM32CubeCLT**
(`/opt/st/stm32cubeclt_1.22.0`), not the distro's `gcc-arm-none-eabi`
package. Pinned in the `Makefile` via `TOOLCHAIN`/`CUBECLT_DIR` so the build
never depends on `$PATH` ordering.

### Build system — `Makefile`

Source discovery is automatic: every `.c`/`.s`/`.ld` under `src/` is picked
up via `find` (recursively, so new subdirectories under `drivers/` etc. just
work), and every directory containing a `.h` becomes an `-I` include path.
`src/test/` is explicitly excluded from that discovery — host-side unit
tests should never get pulled into the cross-compiled firmware image.

| Target | What it does |
|---|---|
| `make` / `make all` | Build `build/firmware.bin` + regenerate `compile_commands.json` |
| `make flash` | Flash via `STM32_Programmer_CLI` over SWD, verify, reset |
| `make debug` | Start `ST-LINK_gdbserver`, attach `arm-none-eabi-gdb` |
| `make dump` | Disassembly listing (`build/firmware.lst`) |
| `make clean` | Remove `build/` |
| `make fromscratch` | `clean` + `all` |

### Editor — cpptools + `compile_commands.json`

`compile_commands.json` is regenerated on every `make`, using the exact same
`CFLAGS` the real build uses (including `-DSTM32L432xx`, which is what
selects the right register header — without it, IntelliSense can't tell
which STM32L4 variant you're building for). `.vscode/settings.json` points
the Microsoft C/C++ extension at that file and turns on semantic
highlighting + enhanced colorization (macros/registers get distinct
coloring). Re-run `make` after moving/renaming files, or the compile
database goes stale.

### Formatting — `.clang-format`

LLVM base style, 4-space indent, 100-column limit.

### Git — `.gitignore`

Ignores build output (`build/`, `*.o`/`.d`/`.elf`/`.bin`/`.hex`/`.map`/`.lst`),
generated editor files (`compile_commands.json`), machine-local editor config
(`.vscode/`), tool logs (`*.log`), and general editor/OS cruft (`*.swp`,
`*~`, `.DS_Store`).

## Firmware behavior

- **`SystemInit()`** (called automatically before `main()`, per CMSIS
  convention) calls `Clock_Init()`, which switches SYSCLK to HSI16 (16MHz),
  enables GPIOB's clock, and configures SysTick for a 1ms interrupt.
- **SysTick** increments a 64-bit millisecond counter (`ms_ticks`) on every
  interrupt; `SysTick_MS()` reads it back safely (short critical section,
  since a 64-bit read isn't atomic on this 32-bit CPU) — usable from
  anywhere in the program.
- **IWDG** (independent watchdog) is configured with a ~2 second timeout.
  `IWDG_Kick()` is called every pass of the superloop in `main()` to refresh
  it. Note: `IWDG_Init()` must actually be called somewhere to arm the
  watchdog — check `main()` if you want it enforcing a real timeout.
- **`main()`** toggles the user LED (GPIOB pin 3 / LD3) in an infinite loop.

```bash
make            # build

```
